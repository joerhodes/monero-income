The plan for feature 003 is done, on branch 003-transaction-csv-export. It passes the constitution check before and after design with no exceptions, and it needs no new dependencies and no database migration.

The export is the last step of a run, after pricing, so any earlier failure means no file is written. The decisions you'd want to check before /speckit-tasks:

- Never a partial file: the run writes a temporary file in the same folder, forces it to disk, then swaps it in over the old export in one step. Readers see either the old file or the new one.
- Owner-only access: the temporary file is created readable and writable by its owner only, whatever your system's default is. The export keeps those permissions when it's swapped in, so it's never readable by others, even mid-write.
- Leftovers from a killed run: a hard kill or power loss can leave a hidden temporary file behind. While writing, a run locks the reports folder itself and first deletes any such leftovers; no other run can be writing then, so they're all dead. Locking the folder rather than using a lock file leaves nothing extra in your reports folder. A second run started at the same time waits briefly for the lock.
- Exact values:
  - xmr is computed with whole-number arithmetic.
  - usd_price is written exactly as stored, never with an exponent (a stored 150 stays 150).
  - usd_value reuses feature 002's exact calculation and rounds half up to two decimals only when writing. I checked the example values in the format contract by running the formulas.
- File format: comma-separated, plain ASCII, LF line endings, nothing ever quoted. I chose LF over the standard CRLF so the file reads cleanly in a terminal and diffs well in git.
- Golden files: this is the project's first report output, so it starts tests/golden/.
  - One file comes from a synthetic database covering final, provisional and unpriced days, a half-cent value, a price of 150, a long price, a 1-piconero amount, a value over $100,000, and out-of-order timestamps.
  - A second file holds the header-only export.
- Auditor documentation: a standalone docs/export-csv.md, linked from the README, so you can hand it over with the file.
