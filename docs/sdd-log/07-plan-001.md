## Prompt

Treat them as decisions, not suggestions; research only the items marked
OPEN.

Stack: Python 3.13+, uv, Typer for the CLI, stdlib sqlite3, pytest, ruff,
mypy --strict, import-linter, pytest-socket. HTTP client: OPEN, but it
must support HTTP Digest auth.

Layout: src/ layout, one package with three layers per the constitution:
- src/monero_income/primitives/: wallet RPC client, database access
- src/monero_income/orchestration/: sync (later features add pricing and
  reporting here), and run(), the entry point that executes a full run 
  (later features add pricing and reporting here)
- src/monero_income/cli.py: thin Typer CLI; parses options and calls run()
import-linter enforces: cli → orchestration → primitives, no skipping.
Command: monero-income

Wallet RPC: call get_transfers with in=true, out=false, pending=false,
failed=false, pool=false. Authenticate with HTTP Digest when a username
is configured.

Timeout: 20 seconds per request by default. OPEN: how a large first sync
avoids timing out (e.g., a longer first-run timeout or fetching in height
ranges).

Sync position: on a first run, start from the start date if one is given.
On a first run with no start date, request all transfers. OPEN: how the
start date (a UTC date) maps to the wallet's height filter, or whether to
filter by timestamp after fetching.
On later runs, request transfers from the last recorded height inclusive,
minus an overlap of 60 blocks; rely on the transaction id rule to skip
already-recorded transactions. Always discard transactions before the
saved start date. Sum all entries that share a transaction id into one
record. Exclude self-transfers. OPEN: how to detect them from the
wallet's response. If self-transfers cannot be reliably detected from 
the response, report this in research.md rather than approximating.

Storage: SQLite file location defaults to `~/.local/share/monero-income/xmr.db` 
but can be overridden by the `db_path` config value; create its parent directory if missing.
Transaction id is the primary key. Store XMR amounts as integer atomic units (piconero), 
exactly as the wallet reports them; convert to XMR only for output. Store 
block height as integer, and the timestamp as integer (UTC Unix seconds), and the UTC calendar 
date as a derived column for later pricing. Store the start date in a key-value meta table 
(key TEXT PRIMARY KEY, value TEXT NOT NULL), not on transaction rows. Track the schema version
with PRAGMA user_version; migrations read and set it. Insert a sync's new records in a 
single transaction. Never emit scientific notation for amounts.

Config: TOML file at ~/.config/monero-income/config.toml. Keys for this
feature: rpc_url, username, password, db_path, since. Later features will
add keys for pricing and output; do not implement them now, but keep
config loading easy to extend. Precedence: command-line option, then
config file, then defaults. The password must be settable without the 
command line, via config file only. Never include the password in any 
output or error message.  A missing config file is not an error; 
defaults apply. Default rpc_url: http://127.0.0.1:18088/json_rpc.
If the config file is readable others, report as a warning.

Errors: every error, including config, storage, and wallet errors, ends
as a clear message and a non-zero exit, never a traceback. Wallet login
failures are reported as login failures.

Scope: feature 001 only. Do not design pricing, CSV output, or summaries.

## What Came Back
I wrote the plan and design artifacts for feature 001. Three things need your decision before /speckit-tasks, and the first could change the design.

1. Self transfers can't be detected with the request you decided (out=false). I checked this against the Monero wallet source rather than relying on the docs:
- A transaction the wallet sends to itself within the same account never appears as incoming. The wallet treats it as change, so nothing needs handling.
- One sent from a different account of the same wallet appears as an ordinary incoming entry, with nothing marking it as the wallet's own. Requesting outgoing entries too fixes this: an incoming entry whose transaction id also appears as outgoing is exactly a self transfer.
- By default get_transfers returns only account 0, so incoming transactions to other accounts are missed.

│    Option     │                Request                │              Result              │
├───────────────┼───────────────────────────────────────┼──────────────────────────────────┤
│ A             │ out=true, all_accounts=true, drop     │ Meets FR-003; covers all         │
│ (recommended) │ incoming entries whose id also        │ accounts                         │
│               │ appears as outgoing                   │                                  │
├───────────────┼───────────────────────────────────────┼──────────────────────────────────┤
│               │                                       │ Records account-to-account self  │
│ B             │ As decided                            │ transfers into account 0 as      │
│               │                                       │ income                           │
├───────────────┼───────────────────────────────────────┼──────────────────────────────────┤
│ C             │ out=false, all_accounts=true          │ Records self transfers from any  │
│               │                                       │ account as income                │
└───────────────┴───────────────────────────────────────┴──────────────────────────────────┘

The design assumes A for now. Switching only changes the request parameters and one filter function.

2. Two constitution conflicts, which Governance says must be amended before implementation:
- Principle III says amounts are Decimal from input to output. Your decided design holds them as integer piconero until output. That's exact and never float, but it doesn't match the wording.
- Principle V says tests use in-memory SQLite. FR-016 (create a missing database file and  folder, never recreate an unreadable one) can only be tested with temporary files. Those tests touch nonetwork.

Both are wording fixes, so a PATCH bump. The same amendment could fix "Operation MUST NOT" in Principle VI.

3. Coverage floor. This feature creates pyproject.toml and needs a number. I proposed 90%.

How I resolved the other open items:
- HTTP client: httpx. It has Digest auth built in, it's typed for mypy, and its mock transport lets its own tests run without sockets.
- Large first sync: the wallet is read in windows of 100,000 blocks, each with the 20-second timeout. A full scan is about 35–40 small requests.
- Start date: filtered by timestamp after fetching, with no date-to-height conversion. The wallet RPC has no date lookup, and an estimate would only be an optimization.
- Height filter: the wallet's min_height is exclusive. "Last recorded height minus 60,     inclusive" therefore means min_height = last − 61.

Smaller choices I made that weren't in your input:
- pytest-cov is added, since the coverage floor needs it.
- An rpc_url containing user:pass@ is rejected, so a password can never leak through a URL in an error message.
- Unknown config keys produce a warning, not an error.
- Exit codes are 0 for success, 1 for errors, 2 for usage errors, and 130 for Ctrl-C.
- A username with no password is allowed, and the wallet decides whether to accept it.
- A start date given on a later run is compared against the one saved in the database.
